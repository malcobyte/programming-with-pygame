# Week 10: Sound & Score

## Learning objectives

By the end of this week, you can:

- Play a one-shot sound effect with `play_sound()` from
  `shared/sound.py`, triggered by a specific event (not every frame).
- Start looping background music with `play_music()`.
- Render text with `pygame.font.Font(...).render()` and draw it with
  `blit()`, the same way you'd draw an image.
- Keep a numeric score variable, update it on events, and display it
  live on screen.

## Functional example: build this together

Open `reference/sound_and_score.py`. It's Weeks 6-7's gem collecting,
with a sound effect on each pickup, looping background music, and a
live score shown in the top-left corner. The sounds in `assets/` are
simple placeholder tones generated by code — swap in your own sound
effects or music whenever you'd like.

Talking points already embedded in the file:

- `play_sound()` is called *inside* the same `if` block that adds to
  the score. What would happen if it were called outside that `if`,
  in the main loop body unconditionally?
- `play_music()` is called once, before the loop starts. What would
  happen if it were called every frame, inside the loop, instead?
- `score_font.render(...)` is called fresh every frame, inside the
  DRAW section. Why not create the text Surface once, like
  `score_font` itself is created once?

## Exercises

Do these in `exercises/`, as separate `.py` files. Copy
`reference/sound_and_score.py` (and its `assets/` folder) into each
one as your starting point.

**1. Volume and fade.**
Set the sound effect and music to noticeably different volumes and
confirm you can hear the difference. Then, when all gems are
collected, call `pygame.mixer.music.fadeout(1000)` to fade the music
out over one second instead of cutting off abruptly.
*Stretch:* look up `pygame.mixer.music.fadeout()`'s argument (it's in
milliseconds) and try a couple of different fade lengths.

**2. A win sound.**
There's a second sound effect, `assets/win.wav`, that isn't used yet.
Play it exactly once — on the frame the *last* gem gets collected, not
every frame after. (Hint: this is the same "only trigger once" pattern
from Week 6/7's win-condition exercises — you'll need to check the
collected count *before* and *after* the collision loop, or track
whether you've already played it.)
*Stretch:* call `stop_music()` right before playing the win sound, so
they don't awkwardly overlap.

**3. Score-based color.**
Change `score_font.render()`'s color argument based on the current
score — for example, white below 30 points, gold at 30 or above.
*Stretch:* also try changing the third argument to `render()` (the
antialiasing boolean) between `True` and `False`, and describe the
visual difference at this font size.

## Weekly project: Scored Collector

In `project/`, build a small game combining sound, music, and score.

**Core requirements:**

- Background music playing throughout.
- A sound effect triggered exactly once per collection event (not
  spamming while touching).
- A live, on-screen score that updates correctly.
- A clear win state when everything is collected — both a visual
  change (text, color, or similar) and a distinct sound.
- Standard game loop rules still apply.

**Stretch goals (optional):**

- Music fadeout on win (Exercise 1).
- Score-based visual feedback (Exercise 3).
